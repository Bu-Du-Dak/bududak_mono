## 자바란

### 자바 언어의 기원

- 최초 개발자: **제임스 고슬링(James Gosling)** (Sun Microsystems)
- 1990년: **그린 프로젝트(Green Project)**
  - 목표: 소비자용 전자제품의 제어 박스 개발
  - 요구: **하드웨어 플랫폼과 무관하게 동작하는 언어** 필요
  - C++ 검토 → 포기 → **오크(Oak) 언어 개발**
- 오크(Oak) → **자바(Java)로 개명**
  - 오크나무가 사무실 근처에 많아서 오크로 이름 지었다는 설명
  - 자바로 개명 이유는 여러 설(인도네시아 섬/커피, 개발자 이름 조합 설 등)

- 1995년: **핫자바(HotJava)** 와 함께 발표
  - 핫자바: 자바 기반 웹브라우저(자바 홍보 목적)
  - WWW 확산과 함께 자바가 주목받기 시작

- 1996년 1월: **JDK 1.0 발표**
- 1998년: 1.2 발표(자바2로 부르기도 함)
  - 1.2~1.4는 1.x로 표현
  - 1.5부터는 Java 5처럼 “1.”을 생략해 부르는 관례 언급

- 2009년: **Oracle이 Sun Microsystems를 인수**
  - 이후 자바 기술을 Oracle이 관리

- (강의 언급) **2023년 9월 기준 최신 버전: Java SE 21**
  - SE: Standard Edition
  - JDK: Java Development Kit

---

### 자바 언어의 특징

- **운영체제/하드웨어 플랫폼 독립적**
  - C/C++은 컴파일/링크 결과가 운영체제/기계에 종속된 실행 파일(EXE)이라 다른 OS에서 실행 불가
  - 자바는 **자바 플랫폼(실행 환경)** 위에서 실행되므로 OS가 달라도 사용 가능
  - 컴파일 결과물: **바이트 코드(bytecode)**

- **완전한 객체지향 언어**
  - C++은 절차적 + 객체지향 모두 가능(하이브리드)
  - Java는 “완전한 객체지향”으로 설명

- **라이브러리 풍부**
  - 데스크톱 응용 프로그램뿐 아니라 웹/네트워크 프로그래밍에도 유용한 라이브러리가 많음(이번 강의에서는 주로 데스크톱 중심)

- **자료형 검사 엄격**
  - 변수 사용 전 자료형 선언 필요
  - 컴파일/실행 과정에서 자료형 검사를 엄격히 수행 → 실행 오류 감소에 도움

- **예외 처리(Exception Handling) 지원**
  - 실행 중 오류 가능 지점에 예외 처리 코드를 작성하면
  - 비정상 종료 대신 정상 흐름으로 회복 가능(교재 6장 내용 예고)

- **멀티 스레드(Multi-thread) 지원**
  - 스레드: 프로그램 내부의 독립적인 실행 흐름
  - 단일 실행 흐름뿐 아니라 여러 스레드를 동시에 실행 가능(교재 12장 내용 예고)

### 자바 플랫폼(Java Platform)

- 자바 프로그램의 **개발과 실행을 위한 환경**
- 구성 요소(2가지)
  1. **JVM(Java Virtual Machine)**
     - 자바 프로그램 실행 환경(구동 엔진)
     - 실행에 필요한 사항 관리/지원
     - 예: **가비지 컬렉션(Garbage Collection)**으로 메모리 회수 자동 수행
  2. **Java API**
     - 애플리케이션 프로그래밍 인터페이스(라이브러리)
     - 자바는 객체지향 → **클래스 라이브러리** 형태
     - 클래스는 **패키지(package)**에 포함되며 패키지는 **계층 구조**

- 실행 환경 구조(개념)
  - 운영체제 위에 자바 플랫폼이 설치되고
  - 그 위에서 JVM이 바이트 코드를 실행

---

### 자바 프로그램 실행 과정

1. **소스 작성**
   - 텍스트 파일
   - 확장자: `.java` (예: `HelloWorld.java`)
2. **컴파일**
   - 컴파일 결과물: `.class` 파일
   - `.class` 파일을 **바이트 코드**라고 부름
   - 소스에 클래스가 여러 개 있으면 **클래스 개수만큼 `.class` 파일 생성**
3. **실행**
   - JVM에서 `.class`(바이트 코드)를 실행

---

### JDK 다운로드/설치 & 컴파일/실행 명령

- JDK = Java Development Kit
  - 자바 플랫폼 + 개발 도구(컴파일러/디버거/문서도구 등) 포함
  - 설치 후 `bin` 폴더에 개발 도구 실행 파일들이 존재

- 다운로드 경로(강의 언급)
  - Oracle Java 페이지에서 OS에 맞는 JDK 다운로드/설치

- 명령 프롬프트에서
  - 컴파일: `javac`
  - 실행: `java`
  - 실행 시: **main 메서드를 가진 클래스**를 대상으로 실행

- 환경 변수
  - `PATH`에 JDK의 `bin` 경로 추가
  - `JAVA_HOME` 환경 변수 생성 후 JDK 설치 경로 지정
  - (강의 언급) 최신 JDK 설치 시 자동 설정되는 경우도 있음

### Eclipse 설치 & 기본 개발 흐름

- Eclipse: 무료 오픈소스 IDE(Eclipse 재단)
- 권장: **Eclipse IDE for Java Developers** 버전 설치
- 설치 방식
  - 설치형(.exe) 또는 압축 파일(압축 해제 = 설치 완료)
- 최초 실행 시 **workspace(작업 공간)** 폴더 지정
  - 프로젝트/소스/.class 등 결과물이 저장되는 공간

- Eclipse에서 기본 개발 순서(강의 흐름)
  1. Java Project 생성
  2. Package 생성(생략 가능: 클래스 생성 시 패키지 지정 가능)
  3. Class 생성 → `.java` 생성과 동일한 의미로 이해
  4. 저장하면 컴파일 수행(일반적으로 IDE가 자동 빌드)
  5. main 메서드를 가진 클래스를 실행(예: Ctrl + F11)
  6. 콘솔에서 출력 확인

### 자바 소스의 구성(주석/클래스/main)

#### 주석(Comment)

- 한 줄 주석
  - `// ...`
- 여러 줄 주석
  - `/* ... */`
- 문서화 주석(자바독)
  - `/** ... */`
  - 클래스 정의 위 또는 메서드 정의 위에 작성
  - `javadoc.exe`(JDK bin 폴더)로 자동 문서 생성에 활용

#### 클래스와 main 메서드

- 자바 프로그램의 기본 구성 단위: **class**
- 데스크톱 응용 프로그램 실행 시작점: **main 메서드**

- main 메서드 시그니처는 고정(형식 변경 불가)
  - `public static void main(String[] args)`

#### public class 파일명 규칙

- 소스에 `public class`가 있으면
  - 파일명은 반드시 `클래스이름.java` 이어야 함

---

### 출력문(기본 형태)

- `System.out.println(...)`
  - `println`: 한 줄 출력 후 줄바꿈
  - C의 `printf`와 달리, 자바는 객체지향 구조로 `System.out`을 통해 메서드를 호출하는 형태로 설명

---

### 배포(Distribution): JAR

- Eclipse에서 배포 = 실행에 필요한 `.class`들을 묶어서 내보내기
- 결과 파일: `.jar` (Java Archive)
- Eclipse 메뉴: 프로젝트 우클릭 → Export → Runnable JAR 등 선택
- 실행(명령 프롬프트)
  - `java -jar 파일이름.jar`

### 객체지향 프로그래밍 핵심 개념

- **추상화(Abstraction)**
  - 모든 구체적 사실을 다 표현하지 않고
  - 전형적/필요한 요소만 추려 **간소화하여 표현**
  - 예: 다양한 실제 자동차들 → 공통 요소 추려 “자동차”라는 클래스 틀 정의

- **클래스(Class)**
  - 객체 생성을 위한 모형(틀)
  - 추상화 과정의 결과물로 설명

- **객체(Object) / 인스턴스(Instance)**
  - 클래스에서 생성된 실체(특정 클래스의 인스턴스)
  - 객체는 각자 다른 **상태(state)**(데이터)를 가질 수 있음

- **데이터 필드(data field) + 메서드(method)**
  - 데이터 필드: 상태 표현(변수)
  - 메서드: 행위(기능)
  - 클래스 안에 데이터와 메서드가 함께 들어있음

- **캡슐화(Encapsulation)**
  - 클래스라는 캡슐 안에 데이터 필드와 메서드가 함께 포함됨

- 객체지향 프로그램의 동작 관점
  - 여러 객체 생성 → 객체 간 상호작용으로 프로그램이 수행됨

---

- 자바 응용 프로그램 시작점은 반드시 아래 형식
  1. 접근 지정자: `public`
  2. 정적: `static`
  3. 반환형: `void`
  4. 이름: `main`
  5. 매개변수: `String[] args`

```java
public static void main(String[] args) {
    // ...
}
```
