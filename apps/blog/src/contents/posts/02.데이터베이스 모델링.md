## 모델링 정의

- 시스템 구축 전 설계 과정
- 현실 데이터를 구조적으로 표현
- 효율적인 데이터 구조 설계

- 결과: 내부 스키마 도출

---

## 모델링 필요성

- 최소 비용 / 시간으로 최대 효율
- 대량 데이터 처리 대응
- 사용자 요구 반영 필수
- 데이터 저장 및 관리 구조 필요

---

## 데이터 모델링 이해

### 데이터 모델링 구성요소

- 데이터 + 프로세스 + 상관관계 기반 설계

#### 데이터 정의 요소

- 의미 / 속성 / 특성 정의

#### 프로세스 정의 요소

- 데이터 처리 기능
- 예: 계산, 보고서 생성

#### 데이터 흐름 관계

- 입력 → 처리 → 결과 흐름

- 실세계 → 추상화 → DB 저장 구조 변환

---

### 데이터 모델 정의

- 데이터 표현을 위한 표기법
- 구조 / 타입 / 관계 정의
- 모델 기반 설계 수행

---

## 데이터베이스 모델링 단계

### 모델링 전체 흐름

- 사용자 요구사항 분석
- 개념적 모델링
- 논리적 모델링
- 물리적 모델링

---

### 요구사항 분석 단계

#### 분석 목적

- 사용자 중심 설계
- 정확한 시스템 구현
- 유지보수 비용 감소

#### 분석 수행 과정

##### 요구사항 도출 단계

- RFP 기반 분석
- 인터뷰 / 현장 조사
- 자료 수집

##### 요구사항 검증 단계

- 정확성 / 완전성 검증
- 기능 / 비기능 요구 정의

##### 요구사항 문서화 단계

- 요구사항 정의서 작성
- 승인 및 추적 관리

---

### 개념 모델링 단계

- 실세계 데이터 추상화
- 표준 표기법 사용
- 결과 도출
  - 개체
  - 관계
  - 속성
  - 제약조건

---

### 논리 모델링 단계

- DBMS 구조에 맞게 변환
- 관계형 / 객체형 모델 적용
- 스키마 정의

---

### 물리 모델링 단계

- 하드웨어 환경 반영
- 저장 구조 설계
- 성능 최적화

---

## ER 모델

### ER 모델 정의

- Entity + Relationship 모델
- 개체와 관계 중심 표현
- 다이어그램 기반 시각화

---

## 개체 (Entity)

### 개체 정의

- 독립적으로 존재하는 객체
- 다른 객체와 구별 가능

- 예: 학생증 신청서

---

### 개체 집합 정의

- 동일 속성 공유 집합
- 예: 학생 집합

---

## 속성 (Attribute)

### 속성 정의

- 개체를 설명하는 요소
- 예: 이름, 학번, 전화번호

---

### 속성 유형 분류

#### 단순 속성 정의

- 더 이상 분해 불가

#### 복합 속성 정의

- 여러 값으로 분해 가능
- 예: 생년월일 → 연 / 월 / 일

#### 단일값 속성 정의

- 값 1개

#### 다중값 속성 정의

- 값 여러 개 가능
- 예: 전화번호

#### 저장 속성 정의

- 실제 저장 데이터

#### 유도 속성 정의

- 계산으로 생성
- 예: 나이

---

## 관계 (Relationship)

### 관계 정의

- 개체 간 연관성
- 업무 과정에서 발생

---

### 관계 집합 정의

- 개체 집합 간 관계의 집합

---

## 제약조건

### 사상수 정의

- 관계 수 표현

- 1:1
- 1:N
- N:1
- N:M

---

### 참가 제약 정의

#### 전체 참가 조건

- 반드시 관계 참여

#### 부분 참가 조건

- 선택적 참여

---

### 키 속성 정의

- 개체를 유일하게 식별
- 중복 불가
- 예: 학번

---

## 특수 개념

### 관계 속성 정의

- 관계에서만 발생하는 데이터
- 예: 수강 신청 시간

---

### 재귀 관계 정의

- 동일 개체 간 관계
- 예: 선수과목

---

### 약한 개체 정의

#### 약한 개체 특징

- 독립적으로 존재 불가
- 다른 개체에 의존

#### 약한 개체 표현

- 이중선 사용
- 키 점선 표시

---

## 전체 정리

- 데이터베이스 모델링 = 현실 데이터를 DB 구조로 변환
- 설계 기준 = 사용자 요구사항

### 모델링 절차 요약

1. 요구사항 분석
2. 개념 모델링
3. 논리 모델링
4. 물리 모델링

### 핵심 구성 요소

- 개체
- 관계
- 속성
- 제약조건

### 설계 시 중요 포인트

- 요구사항 기반 설계
- 관계는 업무에서 발생
- 속성은 복합적 특성 보유
- 키는 반드시 유일성 유지

- 좋은 모델링 = 성능 + 유지보수 + 확장성 확보
